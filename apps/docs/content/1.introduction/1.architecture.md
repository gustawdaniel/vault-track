# Architecture

VaultTracker is built as a **TurboRepo monorepo** with four main applications:

| App | Technology | Purpose |
|-----|-----------|---------|
| `apps/ui` | Nuxt 4 (SPA) | Main user-facing application |
| `apps/backend` | Fastify | REST API server |
| `apps/admin` | Nuxt 4 (SSR) | Admin dashboard |
| `apps/docs` | Docus | Documentation site |

## Frontend — Offline-First SPA

The UI is a **client-side only** Nuxt 4 application (`ssr: false`). All financial data is stored locally in the browser using **IndexedDB**, making the app:

- **Instant** — no network latency for reads/writes
- **Private** — your data never leaves your device unless you opt into sync
- **Available offline** — works without an internet connection

State management uses **Pinia** stores that persist to IndexedDB automatically.

## Backend — Fastify API

The backend provides server-side features that require infrastructure:

- **Currency Exchange Rates** — daily updated rates for multi-currency support
- **Receipt Scanning** — AI-powered OCR via LLM to extract transaction data from photos
- **Data Sync** — encrypted synchronization between devices using Redis or filesystem storage
- **User Management** — authentication and user accounts
- **Admin API** — server administration endpoints

The API is documented via **Swagger/OpenAPI** at `/documentation`.


## Key Technologies

- **Framework**: [Nuxt 4](https://nuxt.com) + [Vue 3](https://vuejs.org)
- **UI Library**: [Nuxt UI](https://ui.nuxt.com) (Tailwind CSS based)
- **State**: [Pinia](https://pinia.vuejs.org) with IndexedDB persistence
- **Backend**: [Fastify](https://fastify.dev) with Zod validation
- **Database**: SQLite (via `better-sqlite3` / Turso) for server-side data
- **Build System**: [TurboRepo](https://turbo.build) for monorepo orchestration
