# Architecture & Technology Stack

## Monorepo Structure

VaultTracker uses [TurboRepo](https://turbo.build) to manage a pnpm workspace with four applications:

```
vault-track/
├── apps/
│   ├── ui/          # Main Nuxt 4 SPA (client-side)
│   ├── backend/     # Fastify REST API
│   ├── admin/       # Admin dashboard (Nuxt 4 SSR)
│   └── docs/        # Documentation (Docus)
├── package.json     # Workspace root
├── turbo.json       # TurboRepo config
└── pnpm-workspace.yaml
```

## Frontend (`apps/ui`)

| Technology | Purpose |
|-----------|---------|
| [Nuxt 4](https://nuxt.com) | Framework (SPA mode, `ssr: false`) |
| [Nuxt UI](https://ui.nuxt.com) | Component library (Tailwind CSS) |
| [Pinia](https://pinia.vuejs.org) | State management |
| [VueUse](https://vueuse.org) | Composables (window size, etc.) |
| IndexedDB (via `idb`) | Local data persistence |
| [Vercel Analytics](https://vercel.com/analytics) | Usage analytics |

### Key Design Decisions

- **Offline-first** — all data stored in IndexedDB, no server required for core features
- **SPA mode** — client-side only rendering for maximum privacy
- **Responsive** — desktop split view (>768px) and mobile list view

## Backend (`apps/backend`)

| Technology | Purpose |
|-----------|---------|
| [Fastify](https://fastify.dev) | HTTP server framework |
| [Zod](https://zod.dev) | Request/response validation |
| SQLite / [Turso](https://turso.tech) | Database |
| [Swagger/OpenAPI](https://swagger.io) | API documentation |

### API Modules

| Module | Prefix | Description |
|--------|--------|-------------|
| Currency | `/api/currency` | Exchange rate data |
| Users | `/api/users` | User authentication & management |
| Admin | `/api/admin` | Server administration |
| Receipts | `/api/receipts` | AI receipt scanning (LLM-powered OCR) |
| Sync | `/api/sync` | Device-to-device data synchronization |

### Sync Architecture

The sync module uses an event-sourced approach:

1. Changes are applied optimistically to local Pinia state
2. Events are persisted to IndexedDB
3. Background sync pushes events to the server
4. Server stores sync data in Redis (production) or filesystem (development)

```typescript
// nuxt.config.ts — storage configuration
storage: {
  sync: process.env.REDIS_URL
    ? { driver: 'redis', url: process.env.REDIS_URL }
    : { driver: 'fs', base: '.data/sync' }
}
```

## Environment Variables

| Variable | Required | Default | Description |
|----------|----------|---------|-------------|
| `BACKEND_URL` | No | `http://localhost:4500/api` | Backend API URL |
| `REDIS_URL` | No | filesystem | Redis URL for sync |
| `TURSO_DATABASE_URL` | No | `file:./local.db` | Database URL |
| `TURSO_AUTH_TOKEN` | No | — | Turso auth token |
| `COOKIE_SECRET` | No | `changeme` | Session cookie secret |
